# Project Agent (AGENT.md)

## Structure
- SvelteKit 2 + Svelte 5 runes (`$state`, `$derived`, `$props`) running on Bun 1.4+. `src/routes/+layout.ts` owns `export const ssr = false` for every route.
- Deploys to Cloudflare Pages via `@sveltejs/adapter-cloudflare` (output `.svelte-kit/cloudflare`, build command `bun run build`). Since nothing is server-rendered, the only code in the Pages Function is `/api/ai*`; the `nodejs_als` compatibility flag is required for the AI SDK (it uses `AsyncLocalStorage`). No environment variables — the Gemini key arrives per-request in the `x-ai-api-key` header.
- Core Modules:
  - `src/lib/table/`: `DataTable.svelte`, `DropdownCellEditor.svelte`, `FormulaHintPopup.svelte`, `store.svelte.ts`, `find.svelte.ts` (pure scanner + find/replace store), `documents.svelte.ts` (multi-file index), `cells.ts`, `formulas.ts` (evaluation + reference remapping), `formula-hints.ts` (completion catalog + caret logic), `range-edit.ts`, `commands.ts`, `schema.ts`, `persistence.ts`.
  - `src/lib/components/`: `Header.svelte` (Files switcher + title + search + alignment control), `RightRibbon.svelte` (AI, find/replace, modules, add row, export, theme, settings — **not** file creation or import), `AiDrawer.svelte`, `FindReplaceDrawer.svelte`, `Icons.svelte`, `settings/` (`AiSection.svelte`, `ModulesSection.svelte`, `ShortcutsSection.svelte`) — rendered on the `/settings` page behind a three-item section rail (`nav.settings-sidebar`), not a modal.
  - `src/lib/modules/`: `types.ts`, `registry.ts`, `module-store.svelte.ts`, `icegrid/` (`index.ts`, `pipeline.ts`, `columns.ts`, `readers.ts`, `schema.ts`, `extract.ts`, `ai.server.ts`, `evidence.ts`, `sanitize.ts`, `derive.ts`, `validate.ts`, `to-table.ts`, `profile.ts`, `confirm.ts`, `confirm.client.ts`, `exchange-rate.ts`, `tariff.ts`, `tariff.server.ts`, `duty-lookup*.ts`, `IcegridSettings.svelte`, `IcegridConfirmDialog.svelte`, `catalogs/`).
  - `src/lib/server/`: `models.ts` (single source of truth for allowed Gemini model ids, shared by both API routes) and `modules/` (server-only AI handler types + static module action registry).
  - `src/lib/data/`: `import.ts`, `export.ts`, `index.ts`. There are no sample datasets — a new workspace opens a blank file.
  - `src/lib/ai/`: `client.ts`, `patches.ts`.
  - `src/lib/ui/`: `position.ts`, `combobox.ts`, `menu.ts`, `ToastHost.svelte`, `toast.svelte.ts`.
  - `src/lib/workspace.svelte.ts`: the single shared document/table/module/toast store + theme, owned above the router so `/settings` and `/` share one live workspace. `createFile`/`newBlankFile`/`openFile`/`deleteFile` are the only entry points that switch files.
  - Root: `src/lib/constants.ts`, `src/lib/types.ts`.
- `src/app.d.ts` exists only to declare the untyped `xlsx-calc` module. Nothing else belongs in it.
- Routes: `src/routes/+layout.svelte`, `src/routes/+page.svelte` (workspace), `src/routes/settings/+page.svelte` (settings; active section is local state, no URL param), `src/routes/api/ai/+server.ts`, `src/routes/api/ai/models/+server.ts`, `src/routes/api/icegrid/duty-lookup/+server.ts`, `src/routes/api/icegrid/exchange-rate/+server.ts`, `src/routes/api/icegrid/tariff-search/+server.ts`.
- Styling: Tailwind CSS v4 (`@tailwindcss/vite`) in `src/app.css` providing utility classes, non-black ultra-thin scrollbars, and design tokens across dark/light themes.
- Document shape: `TableData` is `{title, columns, rows, cellAlign?}`. `cellAlign` maps `rowId::columnId` to `left|center|right` and is part of the persisted v2 document, the undo history, and the document hash.
- Storage layout: `xlsx-ai:docs:v1` holds `{docs:[{id,title,updatedAt}], activeId}`; each file's rows live at `xlsx-ai:doc:<id>`. The table store takes its storage key as a getter so the active file can change without rebuilding the adapter.
- Tests: `tests/app/*.test.ts` (host app: table, documents, data, formulas, ai, modules framework) and `tests/icegrid/*.test.ts` (the ICEGrid module, with its corpus fixtures under `tests/icegrid/fixtures/`), run via `bun test`; `e2e/table.spec.ts` runs via `bun run test:e2e` (chromium only). One directory per module under `tests/` — keep module tests out of `tests/app/`.



## Blunders
- Importing `pdfjs-dist/build/pdf.mjs` directly throws `ReferenceError: DOMMatrix is not defined` in headless Node/Bun test runners. Fixed by importing from `pdfjs-dist/legacy/build/pdf.mjs`.
- Pressing Enter in inline cell editor bubbled keydown event to table scroll wrapper, triggering table-level edit handler and immediately re-opening edit mode. Fixed by calling `e.stopPropagation()` in `handleEditorKeyDown`.
- Referencing `formattedModels.some(...)` during `allRawModels.map(...)` definition in `models/+server.ts` caused a TDZ 500 crash on any response with `gemini-2.5-flash`. Fixed by precomputing `hasDefaultModel` upfront.
- Binding `bind:this` on Svelte 5 template elements to arrow functions errors during `svelte-check`. Fixed by using custom Svelte action `use:registerCellNode`.
- Empty or 0-row tables were discarded on reload because `store.rows.length === 0` fallback in `+page.svelte` replaced them with SaaS sample. Fixed by returning explicit hydration status `{ status: 'restored' | 'missing' | 'invalid' }`.
- Exporting tables with duplicate column names dropped data when mapped directly to object keys. Fixed by disambiguating headers with `buildUniqueExportHeaders()`.
- Missing `@types/bun` in devDependencies caused `svelte-check` to fail in CI on `tests/setup.ts`. Fixed by installing `@types/bun` and adding explicit `PluginBuilder` typing.
- **Every ICEGrid import failed with "Gemini could not complete the request."** Gemini's `responseSchema` only permits `enum` on STRING types, and `reportVersion: z.literal(1)` compiles to `{type:"number",enum:[1]}` -> HTTP 400 on every call. Fixed by generating `IcegridExtractionSchema` (rows + warnings only) and stamping `reportVersion`/`sourceFiles` server-side. `tests/icegrid/schema.test.ts` now asserts the emitted responseSchema contains no non-string enum. **Never put a numeric/boolean `z.literal` or `z.enum` in a schema handed to `generateObject` with the Google provider.**
- `/api/ai` collapsed every provider failure into one opaque 502 string, which is what made the above undebuggable. It now forwards the provider's own message and reads `statusCode` (the AI SDK's field) rather than `status`.
- `store.loadTable()` cleared undo history, so the "instant load, undo via Ctrl+Z" affordance on imports silently destroyed unsaved work. It now pushes history unless the current document is empty.
- `tbody` ends with a `tr.grid-filler` so the `sticky bottom-0` summary row lands on the floor of the grid instead of floating mid-page when rows are shorter than the viewport. Consequence: `tbody tr.data-row:last-child` never matches — use `.locator('tr.data-row').last()`.
- **The grid rendered blank in Firefox and fine in Chrome.** `min-w-max` (`min-width: max-content`) on a `table-fixed` table makes Firefox compute the table at ~17.9M px wide, pushing every column off-screen; Chrome clamps it. Fixed by giving the table an explicit summed pixel width (`gridW`) plus `min-width: 100%`, so no intrinsic sizing is involved. **Never put `max-content` sizing on a fixed-layout table.**
- Firefox hands a `height: 100%` table's leftover height to any row that declares no height of its own, so with the width fixed it inflated `thead tr` to 190px. `tr.grid-filler` must be the *only* row without a declared height — hence `h-8` on the header row and no `h-full` on the filler.
- Dismissing a dropdown by clicking outside it silently overwrote the cell with the **first** option: the outside-click handler called a `commitSelectedOrCurrent()` that fell back to `filteredOptions[highlightIndex]`, and `highlightIndex` starts at 0. Clicking away is a dismissal — it now calls `onCancel()`.
- Ribbon buttons render their own tooltip span; adding a native `title` too produced two stacked tooltips. Use `aria-label` only.
- Long cell text bled across the column border into the neighbouring cell. `truncate` was on an **inline** `<span>`, where `overflow: hidden` does nothing. Fixed with `block w-full` on `.cell-text-display` plus `overflow-hidden` on the `td`.
- `focus` fires between `mousedown` and `click`, so the cell's `onfocus` handler reset the selection anchor and collapsed every shift-click to a single cell. `onmousedown` now records `pointerExtend` for `onfocus` to read.
- **Clicking Settings popped a file-chooser.** `$effect(() => registerImportPicker?.(...))` returned the registered function, and Svelte runs an effect's return value as teardown — so unmounting the ribbon on navigation called `fileInput.click()`. **Never let an `$effect` body implicitly return anything but a cleanup function; always use a braced body.** Guarded by a `page.on('filechooser')` assertion in the settings e2e test.
- File creation/import belongs to the Files menu in the header only. The ribbon duplicated both; the hidden `<input type="file">` for import now lives in `src/routes/+page.svelte` next to the Files menu that opens it.
- History cloning: the store hashed the whole document with `JSON.stringify` on every reactive read to compute `isDirty`, which nothing consumed — flush-on-unload in `+layout.svelte` is unconditional. Hash and `isDirty` are gone; snapshots are shallow clones (`Row` and `CellAlignMap` are flat by type). `Column.dropdown` is the **one** nested field and must stay deep-cloned, or undo restores a config the live state can still mutate.
- A failed `localStorage` write used to set `saveStatus = 'error'` and stop there, with no reader — edits silently stayed in memory. `createTableStore` now takes `onSaveError`, wired to a toast in `workspace.svelte.ts`.
- ICEGrid schedule data (168 KB) is deferred: `icegridModule.run` dynamically imports `pipeline.ts`, which is the only static path to `catalogs/generated/schedules.ts`. `SCHEDULES_PROVENANCE` lives in its own `provenance.ts` because `IcegridSettings.svelte` displays it eagerly — never re-export it from `schedules.ts`, that pulls the blob back into the initial payload.
- Tests run on `bun:test`, not Vitest. There is no Vitest config; `bun test tests` is the whole unit runner.
- `ai` v7 no longer depends on `@opentelemetry/api`, so the `src/lib/server/noop-otel.ts` shim, its `resolve.alias`, and `ssr.noExternal: ['ai']` are all deleted. `vite.config.ts` is back to plugins only — do not reintroduce the workaround without checking `bun pm ls` for the dependency first.
- Zod 4 + AI SDK 7 move together: `ai` v4 pinned `zod ^3.23.8` and converted schemas through v3 internals, so `generateObject` breaks if only Zod is bumped. On the SDK side `system:` is now `instructions:`, `LanguageModelV1` is `LanguageModel`; on the Zod side `z.ZodTypeAny` is `z.ZodType` and `error.format()` is `z.treeifyError(error)`.
- Excel export formatted numbers with `#,##0.##`, which caused Excel/OnlyOffice to render literal trailing dots on all integer cells (`1.`, `120.`, etc.). `NUMBER_FORMAT` now leaves `number` unformatted so Excel uses default General formatting.
- ICEGrid amounts (`UnitPrice`, `ProductAmount`, `Taxable_Value`, `IGST_Amount`, `GSTCCessAmount`) were typed `currency` instead of `number`, which prepended `$` dollar signs in the UI and xlsx export. They are now `number` columns.
- **ICEGrid fields were cleared to `null` because of our own PDF extractor, not the model.** Two separate causes. Descriptions were held to the same contiguous-value rule as codes and amounts, though PDF layout interleaves other columns between the wrapped lines of one cell; `Description` and `dbk_desc` now only need a verified quote that *overlaps* the value in either direction. Separately, `verifyEvidenceSpan` demanded the quote appear contiguously, so a correctly copied row died whenever extraction reordered or split the columns; it now falls back to order-free token matching for quotes of three tokens or more. Neither relaxation forgives arithmetic: the fabricated part of a fabricated quote is itself a token, and every non-prose field still needs its value contained in the model's own quote.

- **A `.min(1)` on the extraction schema turned a correct answer into a 502.** Handed a packing list with no commercial invoice, Gemini answered `{rows: [], warnings: ["No commercial invoice file was provided..."]}` - well-formed, correct, and with the reason attached. `IcegridExtractionSchema` required at least one row, so the AI SDK rejected the response as `NoObjectGeneratedError` and the only useful part of it never reached the user. The schema now accepts zero rows and `pipeline.ts` fails the import right after extraction, quoting the model's warnings, before it spends a duty lookup and a confirmation dialog on an empty table. Same family as the `z.literal(1)` blunder above: **never constrain the shape of a legitimate answer in a schema handed to `generateObject`** - validate it where you can build a message.

- **DGFT's own ITC-HS lookup searches by description, and that is where every offered tariff code comes from.** `POST www.dgft.gov.in/CP/webHP?requestType=ApplicationRH&actionVal=preview&screenId=90000802&itc-code=<q>` takes *either* a code prefix or plain text in the same parameter, needs no session or key, and answers with `itcCode`/`itcDescription`. `wall clock` returns the two tariff lines that name one; `9403` returns the heading's 16 filable children. The `type` parameter its own page sends is inert - `desc` 500s and omitting it searches both columns anyway. It sends no CORS headers, hence `/api/icegrid/tariff-search`.
- **The DGFT match is literal, which is the entire reason a model is involved.** `bed linen` finds eight entries and `cotton bed sheet` finds none; `wooden furniture` finds five and `furniture of wood` finds none - word order matters and there is no stemming. So `ai.server.ts`'s `classify` action asks Gemini for **search phrases in tariff vocabulary, never for a code**, and `IcegridSearchTermsSchema` has no field a code could travel in. Codes only ever enter through DGFT's answer, so a hallucinated one cannot reach the dialog: it would have to exist in the schedule to come back at all. This is deliberately *not* a relaxation of the extractor's "never infer HS codes" rule - that rule governs writing a value with fabricated evidence, and nothing here writes anything a human did not pick.
- Only an 8-digit code is filable, so `isFilableRitc` (not "is RITCCode non-empty") decides whether a row is settled. A printed `9403` narrows the answer without being one and goes to the dialog's unclassified section, keyed by `unclassifiedKey` = printed digits + lowercased description, so two lines of the same goods under the same heading are one decision. DGFT answers a search at every level of the hierarchy, so `filableCandidates` drops the 2-, 4- and 6-digit rows.
- **Never make a model echo back a key you generated.** An unclassified item's key is `printed digits | lowercased description`, so a real one is `|wall clock 24" face 61 cm,matt antq brass` - pipes, quotes and commas the model had to reproduce character for character or the `termsByKey.get` missed and the item silently got no phrases. On a 32-row clock invoice that left every single item with an empty picker. Both model calls now hand out short opaque ids (`i0`, `r0`) and map back server-side; `tests/icegrid/classify.test.ts` asserts the prompt contains the id and *not* the key.
- **`requestTariffClassification` must not swallow its failure**, for the same reason `/api/ai` must not - and here it is worse than an opaque error, because an empty candidate list renders as "the schedule has no such code" when it means "we never asked". It returns warnings, the pipeline adds them to the run, and `IcegridConfirmInput.classifyWarning` puts the reason in the dialog where the user is looking.
- **A flat `slice(MAX_TARIFF_QUERIES)` over every item's phrases starves the tail of the list.** Thirty items times three phrases is ninety queries against a budget of forty, so items past roughly the thirteenth got zero searches with no way to tell that apart from the schedule having no answer. `allocateQueries` spends the budget round-robin, so every item gets its best phrase before any gets its second. `searchTariffBatch` also runs in chunks of 8 rather than firing a hundred simultaneous requests at a government service.
- **A cache keyed by the wrong thing filed one code's goods against another's drawback claim.** The dialog cached duty-structure results per *item*, so picking code A then switching to B short-circuited on A's cache: the dropdown kept offering A's serials and `perItem.drawback_schno` kept A's answer, next to B's tariff code. It is keyed by **code** now (`dutyByCode[chosen]`), which makes reading another code's options unexpressible rather than merely tested, and `clearCodeDerived` drops `drawback_schno` and `RODTEP` on every code change - they are consequences of the code. `IGST_PaymentStatus` and `IGST_Rate` survive, because those are decisions about the shipment, not the classification.
- `normalizeRitcCode` in `duty-lookup.ts` is the module's one digits-only normaliser; `tariff.ts` briefly shipped a byte-identical `tariffDigits` beside it.
- **Classification is two Gemini calls, and the second one only reorders.** The first returns search phrases; the second is handed each item's candidate list - real DGFT rows, code and official wording - and orders it. `applyRanking` then keeps only codes that were on the list it was given and re-appends anything it omitted, so the worst a bad ranking can do is put the right code second. Both schemas are in the `responseSchema` guard test, and `IcegridSearchTermsSchema` deliberately has no field a code could travel in.
- **The local word-overlap score must not decide what the ranker may consider.** `rankTariffCandidates` is called with `RANKING_SHORTLIST` (25), not the six the user finally sees, and the cap is applied *after* the model has ordered them. Measured on the live master: heading `9403` has 16 filable children, and lexical ranking puts `94039100 Parts: Of wood` at the top for a finished wooden shelf - a parts entry scores on `wood` while `Other wooden furniture` scores the same. Trimming to six first would have handed the model a list already shaped by that mistake.
- **Ranking a shortlist by "shortest description" puts `Other` first every time**, which is the one entry a filer should never be nudged toward - the drawback side of this module already warns whenever it falls back to a residual. `rankTariffCandidates` sinks residual entries (a description with no non-stop-word tokens) below everything else, and matches tokens by 4-character prefix so `wood` reaches `wooden` - exact equality scored `SIDE TABLE MANGO WOOD` against `Other wooden furniture` at zero and the residual won the tie.
- Picking a code in the dialog fires its duty lookup immediately (`chooseRitc`), prefilling the drawback serial and RoDTEP verdict the way `deriveRows` would. Without it those would be settled silently after confirmation - the exact unwitnessed classification the per-tariff section exists to prevent. `newlyAssignedRitcs` then re-runs `requestDutyLookups` for those codes before the final derivation, so `buildDrawbackOptions` carries them into the grid.
- **A regex in a JSDoc comment can end the comment.** `\s*/g` contains `*/`, so a sentence explaining a pattern closed the block early and produced a dozen syntax errors pointing at innocent lines further down the file. Describe a pattern in prose, or leave the flags off.

- **`impexcube.in` looks unscrapeable and is not.** A plain GET returns a 26 KB shell with header-only tables and no tariff code anywhere, identically from curl, Bun `fetch` and a same-origin `fetch` inside the page - so it reads like session-gating or bot-blocking. It is neither: the tables are filled by JSON POSTs to `/DutyStructureExport/FillDBK` and `/DutyStructureExport/GetDetails` (`{RITC, Country:'null', Mode:'DBK'|'RODEP'}`), which need no session, no cookies and no key. Reading the network log while filtered to the page URL hides them; the endpoints only appear in an unfiltered read. Drawback answers key on the four-digit heading, RoDTEP on all eight digits.

- **A dropdown option's label must not repeat its own value.** `dropdownOptionLabel` renders `${value} — ${label}`, so a builder that also prefixed the serial printed `9403B — 9403B — Other furniture…`. Labels carry the description alone; the grid adds the value.
- **A dependent dropdown offered every other row's value.** `resolveDropdownOptions` filters options by `parentValue`, then ran a second pass appending every value already present in the column — for any `allowCustom` column, which drawback is. So one heading's serials appeared under another, bare: no description, and no `fills` behind them, so picking one wrote the serial and coupled nothing. That harvest is now scoped to the current row when the column depends on another. **Independent custom columns still harvest the whole grid — that is what makes a free-text dropdown offer what the column already contains.**
- **`set()` in `derive.ts` is first-wins** (`if (!blank(row[header])) return`), which is why `dbk_unit` is never blank after an import: the schedule's unit is written at the drawback block, and if the serial has none, the later `set('dbk_unit', row.QuantityUnit, 'derived')` backfills the invoiced unit. A grid-side coupling that blanked the unit instead would have made the same row read differently depending on whether a human or the importer chose the serial. **Before making the grid write a field the pipeline also derives, check what `deriveRows` leaves in it — the fallbacks are ordered, not absent.**
- **A derivation runs once, at import, and nothing re-runs it.** `PerUnit`, `dbk_unit` and `SQCQTY` all read `QuantityUnit`, so a `QuantityUnit` the extractor could not evidence — `sanitize.ts` clears any value with no supporting quote — left all three permanently blank, and filling the unit by hand afterwards did nothing. The symptom read like a coupling bug; three columns empty at once was the tell, since they share exactly one input. **When a derived column is unexpectedly blank, check whether its *input* was blank at import before suspecting the code that reads it.** `QuantityUnit`'s dropdown now carries `fillsIfBlank` for the two it copies, which is what makes a late unit still feed them.
- **Global `RegExp` with `/g` flag retains state across `.test()` calls via `lastIndex`.** `compileSearchPattern` must return a stateless (non-global) regex for predicate testing across cells, and construct global regexes strictly on-demand for string replacements.

## Notes & Discoveries
- **An import now stops and asks before it writes.** `pipeline.ts` runs `deriveRows` **twice**: once to produce what the extractor, the schedules and the duty lookup propose, which is what fills `IcegridConfirmDialog`, and again over `applyIcegridAnswers(report.rows, answers)` once the filer confirms. That ordering is the whole trick - `set()` is fill-only, so a confirmed answer sits on the raw row before derivation and every consequence recomputes off it: a changed drawback serial pulls its own rate, description, ROSL values and unit, and an IGST status changed to `LUT` zeroes the tax block. Applying answers *after* a single pass would have needed a second set of rules to un-fill what the first pass wrote. Blank answers are skipped rather than written, or confirming would erase the values the schedules are about to supply.
- The dialog asks per **unique RITC**, not per row - `drawback_schno`, `RODTEP`, `IGST_PaymentStatus`, `IGST_Rate` are properties of a tariff code - plus one invoice-wide block (`RewardItem`, `StateOrigin`, `DistrictOrigin`, `EndUse`, currency and rate). `confirm.client.ts` `mount()`s it onto `document.body` and awaits a promise, because the pipeline is plain TypeScript with no component around it and a module may not reach into workspace UI state. With no `document` (the test runner) it resolves the proposals unchanged, which is what keeps `pipeline.test.ts` headless. Cancelling resolves `null` and the pipeline throws an `AbortError`, which `RightRibbon` toasts as info rather than red; the run's `AbortSignal` also closes the dialog, so cancelling from the progress banner cannot strand it on screen.
- **`impexcube.in/Home/LoadExRate` answers a plain GET with the whole rate board** - every currency, both directions - no POST body, session or key, unlike the duty-structure endpoints next door. Exports convert at the `Export` column; `Import` is the other direction of the same notification and would overstate every `Taxable_Value`. It sends no CORS headers, hence `/api/icegrid/exchange-rate`. Currency is detected by scanning the documents for three-letter codes the board actually lists, with `INR` excluded - an Indian exporter's letterhead, GSTIN block and rupee totals name it on every document without the goods being invoiced in it.
- `IcegridProfile` holds only what is genuinely constant across shipments (`endUse`, `rewardItem`, `igstPaymentStatus`, `applicableExpSchemes`, `ftaCode`). State and district of origin, currency and exchange rate were removed from it: they vary per consignment, so the confirmation dialog asks against the shipment in hand instead of remembering a default that is wrong as often as it is right.
- Formulas: a cell stores the string the user typed (`=SUM(B2:B9)`); `src/lib/table/formulas.ts` evaluates it with `xlsx-calc` (MIT, ~10 KB gz) into `store.resolvedRows`, which feeds the grid, search, sort, summaries and export. `store.rows` is never rewritten and `store.rawCell()` is what the editor opens on — that split is what shows the result in the cell and the formula in the editor. `normalizeCellValue` passes any `=`-prefixed string through untouched; without that guard a numeric column strips `=SUM(B2:B9)` down to the digits it contains.
- `remapFormulaRefs(formula, mapRow, mapCol, …)` is the one primitive behind filling, inserting and deleting — each is just a different pair of index maps (`insertedAt` / `removedAt` / `unchanged`, or an offset for a fill). A reference that maps to nothing becomes `#REF!`. **A structural edit maps `$`-pinned references too** (`mapAbsolute`): `$A$4` means "row 4 wherever it ends up", so inserting above it still moves it — only a *fill* leaves absolutes where they are. `store.duplicateRow`/`deleteRow`/`deleteColumn` all run `remapRowFormulas` over the grid; `addRow` appends at the end, so nothing shifts and it needs no rewrite.
- `offsetFormulaRefs` is the fill case of the above: it steps every relative reference by a row/column delta, leaves `$`-pinned parts alone, and returns `#REF!` for anything pushed off the grid rather than clamping it. Its reference scanner skips quoted text and refuses a match whose neighbours make it part of a longer word — `LOG10(` is a function name, not `LOG` plus row 10, and an open paren after the digits is what tells them apart.
- The fill handle is the `span.active-cell-handle` on the active cell; it was `pointer-events-none` decoration before. A fill covers **one axis only** (whichever the drag went further in), because Excel fills a line and a diagonal drag has to resolve to one. The drag ends on a `svelte:window` mouseup, so releasing outside the grid still commits.
- Formula addressing is the **exported workbook's**, not the array's: row 1 is the header, data starts at row 2, so the grid's row gutter counts from 2. That is what lets a formula survive export and re-import with no reference rewriting. `write-excel-file` takes the expression *without* its leading `=` (`type: 'Formula'`, `value: 'SUM(B2:B9)'`) — passing it through verbatim writes an off-spec `<f>=SUM(..)</f>`. It has no slot for a cached result, so an exported formula cell reads blank in viewers that do not recalculate; Excel, LibreOffice and Sheets all do.
- Grid selection lives in the table store (`setSelection(cell, extend)` / `selectionRect` / `activeCell`), not in `DataTable`, so the header's alignment control acts on the same range the grid shows. Anchor + focus; equal means one cell.
- Run e2e with `bun run test:e2e`, never a bare `playwright test`. The Playwright config points `webServer` at `vite preview`, which serves the *last* `vite build` output — a bare run silently tests a stale bundle and passes on code you just changed.
- The colour system lives entirely in `src/app.css`. Both ramps are generated in OKLCH: one neutral hue (265) with chroma held **flat** across the surface steps, so an elevated surface reads as lighter rather than bluer. Every text/surface and accent/surface pair — including accent text on its own `-bg` tint — is verified at >= 4.5:1 before the hexes are committed. If you change a hex, re-check the pair; the dark and light accents are deliberately different lightnesses (dark `--accent-primary` is `#10b981`, light is `#14714e`), not the same colour.
- Never write a raw Tailwind palette colour (`text-emerald-400`, `bg-rose-500/10`, `text-white`) in a component. Those are fixed shades that cannot respond to the theme — they were the reason light mode shipped a "Configured" pill at 1.66:1. Use `--accent-{primary,rose,amber,sky,purple}` plus their `-bg` / `-border` tints, and `--text-inverse` for text sitting on an accent fill.
- `--font-sans` / `--font-mono` are declared in `@theme`, not `:root`. In `:root` they are inert and Tailwind's `font-mono` utility silently falls back to its own stack, which is what used to happen to every mono cell in the grid.
- Light mode's surface order is `bg` < `surface-2` < `surface-1`, the inverse of dark mode's `bg` < `surface-1` < `surface-2`. That predates this palette and components rely on it; check both themes when you touch a surface token.
- Cell alignment is document state: `TableData.cellAlign` maps `rowId::columnId` -> `left|center|right`, defaulting per column type via `defaultAlignForType` (numbers right, everything else left — Excel's own rule). It is undoable, persisted in the v2 document, and orphan keys are pruned in `sanitizeAndNormalizeTableData`. It survives `.xlsx` export — but only because `RightRibbon.svelte` passes `store.cellAlign` into `downloadTableAsXlsx`; the store is not consulted inside `export.ts`.
- Excel-Style Roving Tabindex: Active cell receives `tabindex="0"` while all other cells are `tabindex="-1"`. Arrow keys navigate cells without entering edit mode, updating focus immediately.
- Floating Popover Overflow: In scrollable table wrappers (`overflow: auto`), popovers are positioned using `position: fixed` with coordinates computed from `computeFloatingPosition()`.
- Two spreadsheet libraries on purpose. `xlsx` (SheetJS CE, patched build from `https://cdn.sheetjs.com/xlsx-0.20.3/xlsx-0.20.3.tgz` to clear `bun audit`) **reads** — it is the only one of the two that handles legacy `.xls`. `write-excel-file` **writes**, because SheetJS CE drops all cell styles on write (styles are a SheetJS Pro feature). Do not consolidate onto ExcelJS: it pulls 77 transitive packages / 22 MB of Node shims and still cannot read `.xls`.
- `buildXlsxSheetData` in `export.ts` is the whole mapping (align, number format, empty cells) and is unit-tested directly, so tests never have to zip a workbook. `exportTableToXlsx` only adds the `.toBlob()` step; `write-excel-file/browser` runs the zip in its own Web Worker.
- CSV Injection Mitigation: Values starting with `=`, `+`, `-`, `@`, `\t`, `\r` are prefixed with `'` during export to neutralize spreadsheet execution vulnerabilities.
- Request Cancellation & Versioning: AI model fetching and chat sessions use versioned request IDs and `AbortController` cancellation to eliminate race conditions.
- ICEGrid catalogs are no longer partly empty: `DISTRICT_OPTIONS` now carries all 725 ICEGATE districts, each scoped to its state via `parentValue`, so `DistrictOrigin` is a real state-dependent dropdown. Nothing derives it — the exporter address names its district in only 4 of 6 corpus fixtures and 3 of those are ambiguous. `StateOrigin` is still derived from the GSTIN's first two digits (`stateCodeFromGstin`), correct in 17/17 shipments.
- Coupled columns: `DropdownOption.fills` maps column id -> `FillValue`, a literal or `{ from: columnId }` read from the same row. `dedupeAndNormalizePatches` expands them, **not** `DataTable.commitEdit` — that is the single funnel every write already passes through (editor commit, paste, `Delete`, AI patches), so coupling reaches all four and inherits the one `pushHistory()` in `applyCellPatches` for a single undo step. Two invariants: a fill is queued *before* the patch that caused it, because the dedupe map is last-wins and an explicit edit must outrank its own fill; and fills expand from incoming patches only — **one hop, never a cascade**, or two coupled columns loop. Payloads resolve through `resolveDropdownOptions(column, row, rows)`, never a flat `options.find()`: a drawback serial is offered under every RITC that carries it, so the same value appears many times with a different payload each.
- `fillsIfBlank` is the same mechanism gated on the target being empty, for a value an option *implies* rather than determines. It is what lets a unit of measure fill a blank `dbk_unit` without overwriting one the document printed or the schedule prescribed: a blank target is itself the evidence that neither spoke, so precedence (extracted > schedule > invoiced unit) falls out with no conditional logic. Blankness is read against the row *before* the batch, like `{ from: … }`, so a paste does not depend on arrival order.
- `fills` is data the module supplies, not machinery core knows about — `duty-lookup.ts` attaches it, `commands.ts` only expands it. It is also the **only** persisted field `sanitizeDropdownConfig` had to learn: that sanitizer rebuilds each option field by field, so a payload not copied there works until the first reload and then silently stops. Both it and `PersistedDropdownOptionSchema` must know about any new option field — `fillsIfBlank` was the second one to learn this.
- ICEGrid columns can be `internal: true`: extracted, evidence-gated and usable by rules, but filtered out of `buildIcegridTableColumns` and `to-table`, so they never reach the grid or the workbook. `NetWeight` is the first — the filing has no slot for it, but `SQCQTY` needs it when the tariff counts in KGS. Two header lists follow from this: `ICEGRID_ALL_HEADERS` (everything extracted, and what evidence spans cite) and `ICEGRID_HEADERS` (the 37 filed columns). **Reach for `ICEGRID_ALL_HEADERS` when building a candidate row and `ICEGRID_HEADERS` when asserting the file's shape.**
- `CLEARED_HEADERS` (`Accessories`, `Total_Package`) is one list, spread into `MECHANICAL_HEADERS` and looped by both `to-table` and `validate`. These are omitted from `IcegridCandidateRowSchema` outright, so the model never spends tokens on an answer that would be discarded on arrival. Adding a header to blank means editing that one list.
- Coupling is for a value a *catalog* determines. For a live relationship between two ordinary columns there is already a formula engine — do not build a second one. `{ from: … }` is a one-hop read of the row as it stands, not a reference that re-evaluates.
- Multi-Cell Replacement: Shift-selected ranges in a single column can be edited simultaneously. `DataTable.svelte` tracks `editTargets`, preserves selection on Enter/Tab, computes intersected options via `resolveDropdownOptionsForRows()`, and applies updates through a single history entry in `updateCellValues()`.
- Find & Replace Engine (`find.svelte.ts` + `FindReplaceDrawer.svelte`):
  - Shortcut is strictly `Ctrl+H` / `Cmd+H` (or right ribbon `🔍` button). `Escape` closes the drawer.
  - One-hot drawer docking: `AiDrawer` and `FindReplaceDrawer` share synchronized transition width (`w-[380px]`) and duration (`200ms ease-out`), ensuring constant width during drawer switching and zero table jitter.
  - Safe replacement: When `useRegex` is false, literal replacement is executed via `escapeRegExp` and string replacement callback to safely preserve `$` characters without triggering regex group expansion.
  - Formulas: Scans raw un-evaluated strings from `storageRow` (`tableStore.rows`) and patches them via atomic `applyCellPatches()` for 1-step undo/redo. Formula cells are protected when searching in values.
  - Scope: Auto-detects multi-cell/column selections on open and features real-time segmented scope switcher (`[ Entire Sheet ]` / `[ In Selection (Range/Col) ]`).

## Workspace Module Rules
- Register browser modules only in `src/lib/modules/registry.ts`; register server AI actions only in `src/lib/server/modules/registry.ts`. Runtime-downloaded modules are not supported.
- Use stable lowercase module IDs. Keep module-specific readers, schemas, prompts, validation, mapping, and server handlers inside the module directory.
- Every module manifest must declare its ribbon label, `IconName`, file-picker accept list, and multiple-selection behavior. `RightRibbon.svelte` must render this metadata generically and must not branch on a module ID.
- Modules receive the active Gemini configuration and JSON/streaming access through `ModuleContext.ai`. Server handlers receive the authenticated model and may use the installed AI SDK; do not create another endpoint, provider, key store, or model selector.
- Modules must respect the run `AbortSignal`, return `TableData` plus warnings, and never directly import or mutate the table store, Settings state, or toast store.
- Disabling a running module must abort it and prevent late results from replacing the table. Add tests for manifests, inputs, cancellation, validation, and returned table data.
